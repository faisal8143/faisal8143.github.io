The data model underneath it all, and why it is shaped this way

Emails and journeys are the visible part. What decides whether a program is maintainable is the model beneath it: which attribute groups exist, what links back to the Contact Key, and whether a given attribute can drive a decision split at all. Click any group to see its data extensions, field types and the reason each one exists.

Contact KeyIdentifies the person across every channel and attribute group. Set in Contact Builder, and immutable once assigned.
Subscriber KeyIdentifies the person in the email channel's All Subscribers list. In an email-only org these look identical — which hides the difference until SMS or push arrives and the same person is created twice.
